## 兼容版本

一次构建产出**三个专属包**，下载时对号入座：

| 整合包版本 | NeoForge | 状态 |
|---|---|---|
| All the Mods 10 **7.2** | 21.1.241 | ✅ 作者实机在用 |
| All the Mods 10 **7.1** | 21.1.234 | ⚠️ 已按该版逐条核验，但未实机长期游玩 |
| All the Mods 10 **7.0** | 21.1.228 | ⚠️ 同上 |

Minecraft 均为 1.21.1。

**为什么要分开发**：整合包升级会改英文原文。7.1→7.2 之间 ATM 动了 13 条任务书正文，
其中 5 条是实质改写（其余是拼写修正）。逐条对过对应模组的 jar 版本之后：

| | 7.1 的原文 | 7.2 的原文 | 模组版本 |
|---|---|---|---|
| 模拟室 | 没有模式之分 | 分训练 / 推演两种模式 | **6.4.1 → 6.5.0，真升级** |
| 灌注塔 | 无视距离，走到哪都生效 | 只在设定的区块范围内生效 | 5.4.2 → 5.4.2，**同一个 jar** |
| 御腐 | 挖矿或怪物掉落 | 9 破片合 1 片簇，再用凝注台合成 | 0.9.6 → 0.9.6，**同一个 jar** |
| AE2 陨石 | 地表或地下都有 | 埋在地下、通常靠近地表 | 19.2.17 → 19.2.17，**同一个 jar** |
| 腐化怪 | 泛指「腐化怪物」 | 点名四种怪物 | 0.9.6 → 0.9.6，**同一个 jar** |

**只有模拟室那条是机制真的变了**（HNN 6.5.0 新增两种模拟模式）。其余四条模组一行代码
没动，是 ATM 把原先写得含糊或干脆写错的描述改准了——比如灌注塔，Pylons 自己的
物品提示与 JEI 说明一直写着「任意距离」，配置里也**没有**给灌注塔的范围选项
（有区块半径的是驱逐塔）；御腐那条「9 破片合 1 片簇 + 凝注台」的配方，0.9.6 的 jar
里本来就带着。

不管是哪一种，**同一句话在两个版本里的原文不同**，拿一份译文通吃就会让 7.1 玩家读到
一段通顺却对不上自己那版的中文——比漏翻危险，因为看不出来。所以按版本分叉。
**请下载与你整合包版本对应的那个包。**

各版的覆盖率（VaultPatcher 硬编码文本按**该版真实字节码**逐条核验）：

| 整合包版本 | 硬编码文本命中 | 目标类找不到 |
|---|---|---|
| 7.2 | 1459 / 1460（99.9%）| 0 |
| 7.1 | 1459 / 1461（99.9%）| 0 |
| 7.0 | 1427 / 1461（97.7%）| 7 |

对不上的那些是因为相关模组在老版本里是别的版本、目标类或那句话不存在，
补丁对那一版本来就不适用；数据库如实记下，不会假装生效。

## 汉化范围

整合包里有 **233 个模组自带官方中文**，本包不做重复翻译，只补齐了覆盖不到、或做错的地方：

| 范围 | 规模 |
|---|---|
| 模组界面 / 物品 / 实体（语言文件层）| **18.4 万余条**。其中 **409 个模组游戏内的中文完全依赖本包**（官方 jar 不带中文），另有 **142 个模组**在官方基础上补齐了缺翻的键 |
| 字节码硬编码文本（语言文件够不着的界面字）| 151 个模块，**1,452 条**（RFTools 系为主）|
| RFTools 全系图形界面 | **24 个** `.gui` 文件 |
| 资源蜜蜂（蜂名 / 基因 / 蜂笼 / 服务器数据迁移）| **467 种蜂** |
| 结构罗盘 / 自然罗盘的结构名 | **799 条** |
| 任务书（FTB Quests）| 官方中文 + 本包补丁 **998 条**。补章节缺口 / 标题副标题；**术语以「任务绑定的物品真名」为单一真源逐条反查对齐**（4168 条带物品的任务全扫，改 161 条标题——照任务书去 JEI 搜不到东西是最伤的 bug）；品牌与维度名按模组自译名 / 社区标准统一（Allthemodium→ATM、Just Dire Things→可怖之物、挖矿维度、彼岸/异界不混用）；修维度写错、配方写错（Insanite/Inanite 混为一谈导致合不出来）等误导性硬错误；修 3 处 `&`+中文 非法颜色码崩溃 |
| 任务书图片艺术字 | 重绘 **200 张**烤进 PNG 的标题图，字取自「该章节已有的中文标题」保证三处一致；配色从原图逐行采样并有对比度保底；带装饰的图只替换文字框，框按连通域算出、边界切到装饰直接报错 |
| **主菜单首页** | 重绘 **14 张**按钮图为中文：单人游戏 / 多人游戏 / 选项 / 退出 / 模组 / 语言 / 租用服务器（字号与字重按玩家反馈调大调粗）；另**新增 2 个按钮**「汉化包主页」「问题反馈」，排在按钮网格最后一行，整合包原有按钮一个未动 |
| Jonn's Trophies 奖杯名 | **2.5 万条**（奖杯名是烤进 NBT 的字符串，但模组把它当翻译键用，所以能翻；四种烘焙形态全覆盖）|
| 机制层修复 | 传送石碑维度名、神秘农业作物名、闪光生物名等 |

**本包还替上游修了一批 bug**：不少模组自带的官方中文本身是错的——例如死亡提示的占位符写错会导致该提示格式化失败、译文张冠李戴（把「步行辅助」写成「夜视」之类）。这些本包都已修正。

## 我该下载哪个包？

[Releases](../../releases) 里有两个文件：

| 文件 | 装在哪 | 谁需要 |
|---|---|---|
| `atm10-zh_cn-client-<补丁版本>-atm<整合包版本>.zip` | **你自己电脑上的 ATM10 实例** | **所有人都要装。** 单人玩家只装这一个就够了 |
| `atm10-zh_cn-server-<补丁版本>-atm<整合包版本>.zip` | **服务器**（开服的那台机器 / 面板） | 只有**开服的人**要装。纯单人玩家不用下 |

文件名里的两个版本号含义不同：`r12` 之类是**补丁自己的版本**，`atm7.2` 才是
**你的整合包版本**。认后者下载。

### 「我玩单人，客户端和服务端是不是都要装？」

**不用，只装客户端包。**

原因：单人模式下 Minecraft 在你自己的进程里跑了一个"内置服务端"，它用的就是你客户端的中文语言。
所以那些"由服务端生成"的文本（蜂笼上的蜂名、建造机的聊天反馈、任务书正文……）在单人模式下天然是中文的。
客户端包里也已经带了修正**旧蜂笼名字**用的服务端脚本（`kubejs/server_scripts/`），单人一样会执行。

**服务端包是给"开服"用的**——只有当别人连到你的服务器上玩时，那台服务器才需要它。

⚠️ **反过来千万别做**：不要把**客户端包**丢到服务器上。里面的作物名配置是纯客户端的，
上了服务器会让所有玩家进服时刷 `error creating crop with id null`。

## 客户端安装（图文步骤）

### 第 1 步：找到你的 ATM10 实例文件夹

就是**含 `mods` 文件夹和 `options.txt` 文件的那一层**。

- **CurseForge / Prism / HMCL**：在启动器里右键实例 → 「打开文件夹」/「浏览实例文件夹」
- 常见路径长这样：`...\.minecraft\versions\All the Mods 10\`

### 第 2 步：解压，并把**整个文件夹**放进去

下载与你整合包版本对应的 `atm10-zh_cn-client-…-atm<版本>.zip` 并解压，会得到一个名叫 `atm10-zh_cn-client` 的文件夹。
**把这个文件夹整个拖进实例目录**，结果应该是：

```
All the Mods 10\          ← 实例根目录
├─ mods\
├─ options.txt
└─ atm10-zh_cn-client\    ← 刚放进来的
   ├─ 双击安装-Windows.bat
   ├─ install.sh
   └─ ...
```

> 放错地方也没关系，安装器会提示你手动输入实例路径。

#### ⚠️ 两种装法，别混着来

| 装法 | 怎么做 | 结果 |
|---|---|---|
| **A. 推荐** | 把解压出的**整个 `atm10-zh_cn-client` 文件夹**放进实例目录，再运行里面的安装器 | 安装器先备份原文件再覆盖，随时可一键回退 |
| **B. 就地解压** | 直接把压缩包**内容**解压到实例根目录，让它当场覆盖 | 汉化确实生效了，但**原文件在解压的那一刻就被盖掉了，没有任何备份** |

**用了 B 之后就不要再运行安装器了**——文件已经在位，再"安装"一次等于让它把每个文件复制到自己头上。
（v7.2-release5 起安装器会识别出这种情况、跳过复制、只补 `options.txt`；更早的版本会直接报错：
`Copy-Item : Cannot overwrite the item ... with itself`。看到这个报错不代表汉化失败——
文件其实已经装好了，只差 `options.txt` 里没启用资源包，进游戏手动启用即可。）

### 第 3 步：运行安装器

- **Windows**：双击 `双击安装-Windows.bat`
- **macOS / Linux**：在该文件夹里终端运行 `bash install.sh`

选 **[1] 应用汉化**。安装器会：

1. 把将被覆盖的原文件备份到 `backups/<时间戳>/`
2. 复制汉化文件到实例
3. 在 `options.txt` 里自动启用汉化资源包（不启用会全英文）
4. 问你要不要装可选的 **JEI 拼音搜索**（能用拼音首字母搜物品，推荐装）

### 第 4 步：确认装上了

进游戏 → **选项 → 资源包**，「ATM10汉化包-<你的版本>」应该在**已启用**那一侧，而且要在列表**最后一位**；
回到主菜单，按钮应该是中文（「单人游戏」「多人游戏」……）。

### 卸载 / 回退

再运行一次安装器，选 **[3] 恢复备份**，一键回到安装前的状态。

## 服务端安装

**只有开服的人需要这一步。单人玩家跳过。**

下载与服务器整合包版本对应的 `atm10-zh_cn-server-…-atm<版本>.zip`，解压后按包内 `请安装前务必看我.md` 覆盖到服务器目录，然后重启服务端。

它带的东西很少，都是**必须由服务端产出**的文本：

| 内容 | 为什么必须在服务端 |
|---|---|
| `config/ftbquests/` 任务书语言 | 任务书数据由服务端下发给所有玩家 |
| `kubejs/server_scripts/` 蜂笼迁移脚本 | 老蜂笼的名字是抓蜂时烤进 NBT 的，只能由服务端改写 |
| `mods/vaultpatcher.jar` + 服务端模块子集 | 建造机聊天反馈等服务端生成的字符串 |

装完后玩家仍需各自安装**客户端包**——服务器管不了你屏幕上的物品名。

## 常见问题

- **我玩单人，要装服务端包吗？** 不用，见[我该下载哪个包？](#我该下载哪个包)。
- **刚装好整合包、还没进过游戏就装汉化，可以吗？** 可以，但资源包顺序要留意。
  这时实例里还没有 `options.txt`（它是游戏退出时才写的）。
  安装器会新建一份，并把汉化包放在资源包列表的**最后一位**——这一点很要紧：
  游戏首次启动会把整合包的十几个内置资源包补进列表，若汉化包不在最后，
  它会被 `mod_resources` 等包整个盖掉（实测能掉到 546 个包里的第 10 位，等于没启用）。
  某些版本尚未实测出内置包顺序，这种情况下安装器**不会伪造**列表，而是提示你
  **先启动一次游戏、退出后再运行一次安装器**——那一次会把汉化包挪到最后，必定正确。
- **实例路径有中文或空格？** 支持。安装器会自动识别；手动输入路径时带不带引号都行。
- **装完还是英文？** 进游戏检查 选项 → 资源包，「ATM10汉化包-<你的版本>」必须启用，**而且要排在列表最后一位**——资源包是后面的覆盖前面的，排在前面等于没启用（安装器一般已自动处理）。
- **模组都是中文，唯独原版的方块 / 物品 / 界面是英文？** 不是汉化包的问题，是**启动器没把原版的中文语言文件下全**。
  这两半的中文来自两个互不相干的地方：模组的中文在各自 jar 里，跟着 `mods/` 走；
  原版的中文是启动器按资源索引单独下载的文件，躺在 `.minecraft/assets/objects/` 下。
  客户端 jar 里**只有英文**，所以后者一缺，原版就整片回落英文，而模组纹丝不动。
  **确认**：翻 `logs/debug.log`，搜 `Failed to load translations for zh_cn from pack vanilla`。
  搜得到就是这个毛病，紧跟着的 `NoSuchFileException` 会把缺的文件路径直接印出来。
  **处理**：在启动器里对这个版本跑一次文件补全 / 修复，补完重进游戏。
  补全不生效就删掉 `.minecraft/assets/indexes/<索引号>.json` 再启动，启动器会重新校验补齐——
  索引号就是日志第一行 `--assetIndex` 后面那个数字。这只动资源缓存，不碰存档和配置。
  拿第三方更新器装的整合包最容易踩这个：更新器只管模组和配置，原版资源归启动器管，两边都以为对方下了。
- **Windows 报 `Cannot overwrite the item ... with itself`？**
  你是先把压缩包内容**直接解压覆盖**到了实例根目录，**然后又运行了一次安装脚本**。
  此时脚本所在目录就是实例目录本身，它要把 `config\xxx.json` 复制到 `config\xxx.json`——同一个文件，PowerShell 拒绝。
  **汉化其实已经装好了**（解压那步就完成了覆盖），只是资源包没在 `options.txt` 里启用。
  处理办法二选一：
  1. 进游戏 → 选项 → 资源包，手动把「ATM10汉化包-<你的版本>」拖到已启用一侧、并确保它在最后一位（最快）；
  2. 换成 v7.2-release5 及以后的安装器，它认得这种装法，会跳过复制、只补 `options.txt`。

  另外提醒：这种装法**没有备份**，恢复功能对它无效。想要能回退，请按上面的[装法 A](#-两种装法别混着来)。
- **安装器说我的版本不是最新／是测试版？** 它装之前会查一次 GitHub 上的最新正式版。
  提示只是提醒，不会拦住安装。不想让它联网就设环境变量 `ATM_SKIP_UPDATE_CHECK=1`。
- **改动不生效？** 资源包类改动 **F3+T** 重载即可；VaultPatcher 硬编码文本、主菜单按钮图需**完整重启游戏**；任务书需**重进世界 / 重连服务器**。
- **蜂笼上的蜂名是英文？** 老蜂笼里的名字是抓蜂时就烙进 NBT 的，资源包改不动它，得靠脚本改写。
  **单人**：装了客户端包就已经带上这个脚本了；**联机**：需要服主装服务端包。
  两种情况都是把蜂笼放进背包待几秒自动转正；**你用命名牌起的名字永远不会被改**。
- **7.2 的任务书说灌注塔「只在设定的区块范围内」生效，是机制改了吗？** 不是，**是上游把话说岔了**，我们照原文译。
  Pylons 在 7.0/7.1/7.2 里是同一个 jar（`pylons-1.21.1-5.4.2.jar`），模组一行没动；
  配置 `pylons-server.toml` 的 `[infusion_pylon]` 也没有范围这一项（有区块半径的是驱逐塔）。
  模组自己的 JEI 说明与物品提示写的都是「任意距离」——灌注塔靠 `infusionChunkloads`
  把自己所在的区块加载起来（**每名玩家仅限一座**）来保持工作，
  所以前提是**那座塔的区块是活的**，不是你人在不在旁边。照旧玩，老教程不受影响。
  （7.2 还给 Protection Pylon 补了任务条目，那个方块 5.4.2 里本来就有，也不是新机制。）
- **JEI 里有一行灰色的 `productivebees:xxx`？** 那是模组给所有语言玩家显示的 ID 行，不是漏翻。

## 已知限制

- **JEI 拼音搜索（jecharacters）会推高启动时的内存峰值。** 它要在整合包全部
  8.7 万条配料上再建一份拼音索引，而那一刻正是启动全程内存占用最高的时候。
  内存紧张的机器上，游戏可能在「Adding N ingredients」这一步被系统杀掉——
  表现是闪退且**不留任何崩溃日志**（没有 crash-report、没有 hs_err、
  也没有 OutOfMemoryError）。遇到这种情况先把 `mods/jecharacters-*.jar`
  挪走再试；它是可选的，不装不影响汉化。
- **Sodium「粒子效果」设置里的原版粒子名无法汉化**（Cloud / Ash / Crit…）。这是 sodium-extra 0.9.3 自身的问题——它连**自己内置的**原版粒子中文都渲染不出来（选项注册时机导致翻译键解析失败），资源包无法干预。模组自定义粒子不受影响。
- 极少数模组把英文**画进了贴图**（技术边界，语言文件无能为力）。
- **MineColonies / 建筑棒里「标签运行时才定」的按钮，文字仍靠左。** 这版 blockui
  不认 `textalign`（上游自己写了这个属性的地方同样贴左，实测 266 处无一生效），
  唯一有效的是 `ButtonImage` 的 `textoffset`，而它要在构建时算好偏移量——
  标签是建筑名、等级名、开/关、下拉框选项这类**运行时才知道**的，宽度算不出来。
  下拉框尤其如此：`DropDownList` 的按钮是它自己建的，文字由数据源在运行时给。
  固定标签的按钮与 48 个界面标题已居中，其余保持原样。
- **CC: Tweaked 电脑终端里的文字无法汉化。** 它不走 Minecraft 的字体，用的是自带的
  `term_font.png`——256×256 的 16×16 字形表，**总共只有 256 个字符，没有任何汉字**。
  中文送进去会按字节被映射成那 256 个图形，屏幕上是一片乱码。所以 `help` 文档、
  程序输出一律保持英文，这是终端本身的物理限制，不是漏翻。
- **建造工具里第三方建筑包的单个蓝图名仍是英文。** 建筑棒的层级是
  风格 → 分类 → 子分类 → 蓝图，前三层（40 个风格、15 个分类、296 个子分类）已全部汉化；
  最后一层的名字取自蓝图文件名，MineColonies 自带包能经注册的小屋方块拿到官方中文，
  stylecolonies / Byzantine 这些第三方包没有翻译键，直接显示文件名。这一层共 3375 个
  不同的词，其中只有 54 个能对上官方译名，其余是 `argo_mid_b`、`aveoneupdio`、
  `0wallbot` 这类段落代号——不打开蓝图本体判断不出指什么。按「拿不准就放弃」整层保持
  原文：半译半英比全英更破坏一致性，猜出来的错译是更严重的一类问题。
- **「Local」分类与本地结构包的说明文字**已在显示层替换，但分类名同时是传给
  `discoverPackAtPath` 的实参（客户端与服务端各存一份），说明文字又在建包那一刻就
  写进了 `pack.json` 落盘，所以**装本包之前就已存在的本地包**读的仍是自己盘上那份旧说明。
- **导览书内容按 7.2 的模组版本生成**（Patchouli / AE2 Guide 等）。三个版本共用同一份：
  实测拿 7.1 的 jar 重跑，4350 条译文有 4347 条照样落位；7.0 少 602 个文件、
  另有 97 条对不上（那几个模组在 7.0 是更老的版本）。老版本读到的导览书可能出现
  该版本没有的条目。语言文件层不受影响。
- **7.0 / 7.1 的包未经实机长期游玩**。它们是按各自版本的真实字节码与英文底本逐条核验
  构建的（覆盖率见[兼容版本](#兼容版本)），但作者本人只玩 7.2。老版本遇到问题请
  [提 Issue](../../issues)，会按该版的数据库定位。
- 各模组自带的官方中文若有错漏，本包尽力修正但不保证穷尽。发现漏翻 / 错译请
  [提 Issue](../../issues)，附截图与位置。
